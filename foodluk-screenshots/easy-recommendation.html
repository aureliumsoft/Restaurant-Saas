Why the current builder feels hard

Foodluk already stores rich rules (min, max, free items, variation price, discount). Belorder never asks for those on the first screen. The loyalty tier screenshot shows the whole creation method in one card.

The screenshot to copy

Palier = one recommendation group

Title the guest can see. Then Ajouter des catégories. The category opens. Then Ajouter des produits. Each product is a row: drag, photo, name, price, Retirer. Réarranger sets the order. Nothing else is required to publish the tier.

Map that 1:1 onto a restaurant recommendation:

  • Titre du palier → name on the dish (“Choose a drink”).
  • 80 points → the only guest rule (“Pick one” or “Pick several”).
  • Boissons → a menu category, not a separate form type.
  • Coca-Cola, Cafe expresso → the products offered from that category.

Hard method today

  • Four different forms: category-single, category-multiple, product-single, product-multiple.
  • You pick a source type before you see any products.
  • Min, max, free quantity, variation limits, discount %, extra cost %, default size, and per-product Free/Remove are open at once.
  • A category often has to be hidden from the website before it can be used as a recommendation pool.
  • The same category cannot be reused easily across sections.

Easy method

  • Start from the dish. Add a recommendation card.
  • Name what the guest reads. French and English, same as Belorder.
  • Add a real menu category. Add only the products to offer, or use the whole category in one click.
  • Choose one rule: pick one, or pick several.
  • Open “More options” only for min, max, and free items.
